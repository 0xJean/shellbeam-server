# Upstream maintenance

[UPSTREAM.md](../UPSTREAM.md) records the exact source baseline, API compatibility level, and attribution. The original README is available in [the baseline Git tree](https://github.com/komari-monitor/komari/tree/1b76b7ad5bc3de6529bb7f0577069b4ac241fec3). Original upstream commits remain in this repository's history.

The maintained branch is `shellbeam`. `main` retains upstream history. The `origin` remote is `0xJean/shellbeam-server`; the `upstream` remote points to `komari-monitor/komari`. Fetch upstream updates explicitly and review them on a branch before integrating; no workflow automatically merges upstream, deploys, deletes packages, generates AI release notes, or publishes images.

An upstream update must retain or deliberately version these interfaces:

- HTTP routes, response envelopes, API key/session authentication, desktop CORS, and the API compatibility version returned by `/api/version`.
- Agent registration and report ingestion, WebSocket/RPC routes, client UUIDs, tokens, and creation timestamps.
- Plugin manifest compatibility, runtime APIs, approvals, persisted plugin state, and notification channels.
- Main SQLite schema, metric-store schema and DSNs, data directories, configuration keys, and migration/recovery APIs.

Product releases set `utils.ServerVersion` to the ShellBeam release version and `utils.VersionHash` to the actual fork commit. Do not set `utils.CurrentVersion` from a ShellBeam tag: clients and plugins use that field as the Komari compatibility version. Changing the API compatibility level requires matching client and plugin verification.

Before release, run the Go tests and vet checks, build both native Linux architectures, validate a fresh installation, test a backup of an existing database, and run the ShellBeam client's API/Agent/plugin smoke checks. Record any unsupported upstream feature rather than exposing a nonfunctional control in the service entry page.

Retain the original copyright statements and full license/notice texts in `LICENSE` and `NOTICE`. Independent fork attribution may be appended without replacing those statements. Release archives and container images include those files and dependency licenses generated by `.github/scripts/collect-notices.py`; regenerate this inventory when dependencies change. The collector includes the selected Go module graph, including transitive/test-only dependencies, and fails when module source or license texts are missing.
